## 1. 概述

本建图方法构建了一个**以评论为节点的异构图**，用于Yelp平台的欺诈评论检测。

### 核心设计思想
- **节点粒度**：每个节点代表一条评论（Review）
- **异构边**：通过用户（R-U-R）、时间（R-T-R）、评分（R-S-R）三个维度建立不同类型的边
- **时间感知**：节点和边都包含详细的时间戳信息
- **丰富特征**：90维节点特征，涵盖用户、产品、评论、时间四大类
- **Transductive 设定**：建图阶段不进行数据划分，划分逻辑放到训练阶段

### 数据集规模（预期）
| 指标 | 数值 |
|------|------|
| 评论数（节点数） | ~39,012 |
| 用户数 | ~20,219 |
| 商家数 | ~601 |
| 欺诈率 | ~11.19% |

## 2. Transductive 设定说明

### 2.1 任务定义

在一个带有时间戳的异构评论图上，对每个评论节点进行**欺诈/非欺诈的节点分类**。时间信息用于帮助模型刻画行为模式和结构演化，提高分类效果。

### 2.2 Transductive vs Inductive

本项目采用 **Transductive 设定**：

| 设定 | 训练时可见 | 测试时可见 | 适用场景 |
|------|-----------|-----------|----------|
| **Transductive** | 整张图结构 + 训练集标签 | 整张图结构 | 静态图、节点分类 |
| Inductive | 训练子图 + 训练集标签 | 新图/新节点 | 动态图、新节点预测 |

### 2.3 建图阶段的职责

在 Transductive 设定下，建图阶段的职责收敛为：

1. **构建完整图**：生成包含所有节点和边的图结构
2. **编码时间信息**：将时间戳显式保存到节点和边上
3. **提取特征和标签**：生成节点特征矩阵和标签数组
4. **不进行数据划分**：train/val/test 划分完全放到训练阶段

### 2.4 训练阶段的职责

训练阶段负责：

1. **加载完整图**：读取 `graph.pkl`、`features.npy`、`labels.npy`
2. **数据划分**：根据时间戳或随机方式划分 train/val/test
3. **模型训练**：利用整张图作为结构上下文，但只在训练集节点上使用标签监督
4. **模型评估**：在验证集和测试集上评估性能

## 3. 整体流程

建图流程在 `main.py` 中定义，分为4个主要步骤：

```
步骤 1/4: 数据预处理 (preprocessor.py)
    ↓
步骤 2/4: 图构建 (edges/graph_builder.py)
    ├── R-U-R边构建 (edges/rur_builder.py)
    ├── R-T-R边构建 (edges/rtr_builder.py)
    └── R-S-R边构建 (edges/rsr_builder.py)
    ↓
步骤 3/4: 特征工程 (features/feature_engineer.py)
    ├── 用户特征 (features/user_features.py)
    ├── 产品特征 (features/product_features.py)
    ├── 评论特征 (features/review_features.py)
    └── 时间特征 (features/temporal_features.py + time2vec.py)
    ↓
步骤 4/4: 标签提取
```

**注意**：不再有"数据划分"步骤，划分逻辑移至训练阶段。

## 4. 图的基本结构

### 4.1 图数据字典结构

构建完成后，图数据保存为 `graph.pkl`，包含以下字段：

```python
graph_data = {
    # 基本信息
    'num_nodes': int,           # 节点数量
    'num_edges': int,           # 边数量
    
    # 边信息
    'edges': list,              # 去重后的边列表 [(r1, r2), ...]
    'edge_attributes': list,    # 边属性列表
    'edges_by_type': {          # 按类型分组的边
        'R-U-R': list,
        'R-T-R': list,
        'R-S-R': list,
    },
    'attributes_by_type': {     # 按类型分组的边属性
        'R-U-R': list,
        'R-T-R': list,
        'R-S-R': list,
    },
    
    # 节点时间戳
    'node_timestamps_raw': np.ndarray,   # [N] 原始时间戳（秒）
    'node_timestamps_norm': np.ndarray,  # [N] 归一化时间戳 [0, 100]
    
    # 边时间戳和属性数组（用于快速访问）
    'edge_timestamps_raw': np.ndarray,   # [E] 原始边时间戳（秒）
    'edge_timestamps_norm': np.ndarray,  # [E] 归一化边时间戳 [0, 100]
    'edge_time_diffs': np.ndarray,       # [E] 边时间差（天）
    'edge_weights': np.ndarray,          # [E] 边权重
    
    # 节点标签（不含划分）
    'node_labels': np.ndarray,  # [N] 节点标签 (0=欺诈, 1=正常)
    
    # 全局时间边界（用于归一化）
    'timestamp_range': {
        'ts_min': float,        # 最小时间戳（秒）
        'ts_max': float,        # 最大时间戳（秒）
    },
    
    # 统计信息
    'statistics': dict,
    
    # 兼容旧字段（后续可移除）
    'timestamps': np.ndarray,       # 同 node_timestamps_norm
    'edge_timestamps': np.ndarray,  # 同 edge_timestamps_norm
}
```

**时间戳说明**：
- `node_timestamps_raw`：节点原始时间戳（秒），即评论发布时间
- `node_timestamps_norm`：节点归一化时间戳，范围 [0, 100]
- `edge_timestamps_raw`：边原始时间戳（秒），定义为 $\max(t_{raw}(i), t_{raw}(j))$
- `edge_timestamps_norm`：边归一化时间戳，范围 [0, 100]
- `edge_time_diffs`：边时间差（天），定义为 $|t_{raw}(i) - t_{raw}(j)|$
- 节点和边使用相同的归一化参数 `ts_min` / `ts_max`

**重要**：`edge_timestamps` 和 `edge_time_diffs` 是两个不同的概念：
- `edge_timestamps`：边的事件时间，表示"这条边何时存在"
- `edge_time_diffs`：两端节点的时间差，表示"两条评论相隔多久"

## 5. 节点设计

### 5.1 节点定义

每个节点代表一条评论，包含以下属性：

| 属性 | 说明 | 类型 |
|------|------|------|
| `review_idx` | 评论的唯一索引 | int |
| `timestamp` | 评论发布时间（归一化到0-100） | float32 |
| `features` | 90维特征向量 | float32[90] |
| `label` | 标签（0=欺诈，1=真实） | int |

### 5.2 节点时间戳

**时间戳的含义**：评论的发布时间

**归一化方式**（在 `graph_builder.py` 的 `_extract_timestamps` 方法中实现）：

```python
# 获取时间戳的秒数
ts_seconds = np.array([t.timestamp() for t in timestamps])

# 归一化到 [0, 100]
ts_min = ts_seconds.min()
ts_max = ts_seconds.max()
timestamps_norm = ((ts_seconds - ts_min) / (ts_max - ts_min) * 100).astype(np.float32)
```

- 数据集中最早的评论 → 0
- 数据集中最晚的评论 → 100
- 其他评论按比例分布在 [0, 100] 区间

## 6. 边的构建

### 6.1 边时间戳的核心定义

对于任意一条边 $e = (i, j, type)$，其中 $i, j$ 是评论节点：

**边事件时间（原始）**：
$$t_{raw}(e) = \max\big( t_{raw}(i),\ t_{raw}(j) \big)$$

**语义说明**：
- 这条边代表"评论 i 和评论 j 之间的某种关系已被观察到"
- 只有当二者都已经发表之后，这种关系才完整存在
- 因此，边的出现时间应不早于两端评论中任何一个

**边时间戳归一化**：
$$t_{norm}(e) = \frac{t_{raw}(e) - ts\_min}{ts\_max - ts\_min} \times 100$$

**要求**：
- 归一化使用与节点相同的 `ts_min` / `ts_max`
- 确保：$t_{norm}(e) \ge \max\big(t_{norm}(i),\ t_{norm}(j)\big)$

**时间差特征**：
$$\Delta t_{raw}(e) = \big| t_{raw}(i) - t_{raw}(j) \big|$$

**注意**："边的事件时间" $t_{raw}(e)$ 与 "两评论之间的时间间隔" $\Delta t_{raw}(e)$ 是两件不同的事情。

---

### 6.2 R-U-R边（Review-User-Review）

**文件位置**：`edges/rur_builder.py`

**连接条件**：同一用户发布的评论之间建立边

**构建方式**：对每个用户的所有评论建立**完全子图（Clique）**

**边权重计算**：基于时间衰减

$$w = \exp\left(-\frac{\Delta t}{\tau}\right)$$

其中：
- $\Delta t$ = 两条评论的时间差（天数）
- $\tau$ = 时间衰减参数，默认45天（`config.RUR_TIME_DECAY_TAU`）

**边时间戳**：两端节点中较晚的时间戳

```python
edge_timestamp = max(t1.timestamp(), t2.timestamp())
```

**边属性结构**：
```python
{
    'edge_type': 'R-U-R',
    'weight': float,           # 时间衰减权重
    'time_diff': int,          # 时间差（天），|t_raw(i) - t_raw(j)|
    'timestamp': float,        # 边事件时间（秒），max(t_raw(i), t_raw(j))
    'timestamp_norm': float,   # 归一化边时间戳 [0, 100]
    'user_idx': int,           # 用户索引
}
```

**欺诈检测意义**：
- 同一用户的评论应表现出一致的行为模式
- 欺诈账号往往在短时间内发布大量评论，时间衰减权重能突出这种异常聚集
- 检测刷单账号、僵尸账号

---

### 6.3 R-T-R边（Review-Temporal-Review）

**文件位置**：`edges/rtr_builder.py`

**连接条件**：同一商家在同一时间窗口（月）内的评论之间建立边

**构建方式**：按 `(business_idx, year_month)` 双重分组，组内建立**完全子图**

**重要说明**：
- "时间窗口条件"（year_month）**仅用于判断是否建边**
- "边事件时间"使用**较晚一端的时间戳**，不使用月份桶

**边权重计算**：基于时间集中度

$$w = \frac{1}{1 + \frac{\Delta t}{s}}$$

其中：
- $\Delta t$ = 两条评论的时间差（天数）
- $s$ = 时间集中度参数，默认7天（`config.RTR_TIME_CONCENTRATION_SCALE`）

**边时间戳**：两端节点中较晚的时间戳

```python
edge_timestamp = max(t1.timestamp(), t2.timestamp())
```

**边属性结构**：
```python
{
    'edge_type': 'R-T-R',
    'weight': float,           # 时间集中度权重
    'time_diff': int,          # 时间差（天），|t_raw(i) - t_raw(j)|
    'timestamp': float,        # 边事件时间（秒），max(t_raw(i), t_raw(j))
    'timestamp_norm': float,   # 归一化边时间戳 [0, 100]
    'year_month': str,         # 年月（仅记录，不作为边时间戳）
    'business_idx': int,       # 商家索引
}
```

**欺诈检测意义**：
- 欺诈团伙往往在短时间内集中攻击某个商家
- 正常评论通常时间分布更均匀
- 检测爆发式评论、刷单攻击

**示例**：
假设商家A在2024年1月有3条评论：
- 评论1：2024-01-05
- 评论2：2024-01-15
- 评论3：2024-01-25

生成的R-T-R边：
1. (评论1, 评论2)：Δt=10天，w = 1/(1+10/7) ≈ 0.41，边时间戳=2024-01-15
2. (评论1, 评论3)：Δt=20天，w = 1/(1+20/7) ≈ 0.26，边时间戳=2024-01-25
3. (评论2, 评论3)：Δt=10天，w = 1/(1+10/7) ≈ 0.41，边时间戳=2024-01-25

### 6.4 R-S-R边（Review-Star-Review）

**文件位置**：`edges/rsr_builder.py`

**连接条件**：同一商家具有相同星级评分的评论之间建立边

**构建方式**：按 `(business_idx, json_stars)` 双重分组，组内建立**完全子图**

**边权重计算**：基于评分极端性

$$w = 1 + \frac{|rating - 3|}{2}$$

- 3星评论：w = 1.0
- 1星或5星评论：w = 2.0
- 2星或4星评论：w = 1.5

**边时间戳**：两端节点中较晚的时间戳

```python
edge_timestamp = max(t1.timestamp(), t2.timestamp())
```

**边属性结构**：
```python
{
    'edge_type': 'R-S-R',
    'weight': float,           # 极端性权重 [1.0, 2.0]
    'rating': int,             # 评分 (1-5)
    'extremity': float,        # 极端性 [0, 1]
    'time_diff': int,          # 时间差（天），|t_raw(i) - t_raw(j)|
    'timestamp': float,        # 边事件时间（秒），max(t_raw(i), t_raw(j))
    'timestamp_norm': float,   # 归一化边时间戳 [0, 100]
    'business_idx': int,       # 商家索引
}
```

**欺诈检测意义**：
- 欺诈评论倾向于给出极端评分（1星或5星）
- 刷单团伙倾向于给相同评分
- 建立完全子图能捕捉这种评分一致性

---

### 6.5 边类型对比总结

| 边类型 | 连接条件 | 权重策略 | 边数占比 | 主要作用 |
|--------|----------|----------|----------|----------|
| R-U-R | 同一用户 | 时间衰减 exp(-Δt/τ) | 0.5-2.5% | 用户行为一致性 |
| R-T-R | 同商家+同月 | 时间集中度 1/(1+Δt/s) | 10-20% | 时间聚集检测 |
| R-S-R | 同商家+同评分 | 评分极端性 | 80-92% | 评分模式识别 |

**边时间戳统一规则**：
- 所有边类型使用相同的时间戳定义：$t_{raw}(e) = \max(t_{raw}(i), t_{raw}(j))$
- 归一化使用与节点相同的 `ts_min` / `ts_max`
- 保证：$t_{norm}(e) \ge \max(t_{norm}(i), t_{norm}(j))$

### 7.2 用户特征（6维）

**文件位置**：`features/user_features.py`

| 特征名 | 全称 | 计算方式 | 可疑性方向 |
|--------|------|----------|------------|
| MRD | Max Reviews per Day | 用户单日最大评论数 | 高值可疑 |
| ARI | Average Review Interval | 用户评论的平均间隔（天） | 低值可疑 |
| RIE | Review Interval Entropy | 评论间隔的熵值 | 低值可疑 |
| PRR | Positive Review Ratio | 正面评价（≥4星）比例 | 极端值可疑 |
| NRR | Negative Review Ratio | 负面评价（≤2星）比例 | 极端值可疑 |
| ARD | Average Rating Deviation | 用户评分与商家平均分的平均偏差 | 高值可疑 |

**RIE（评论间隔熵）计算**：
```python
# 时间桶定义
INTERVAL_BINS = [0, 1, 7, 30, float('inf')]  # 0-1天, 1-7天, 7-30天, 30+天

# 计算间隔分布的熵
hist, _ = np.histogram(intervals, bins=INTERVAL_BINS)
probs = hist / hist.sum()
rie = -np.sum(probs * np.log(probs + 1e-10))
```

### 7.5 时间特征（68维）

**文件位置**：`features/temporal_features.py` + `features/time2vec.py`

#### TSLR（1维）

| 特征名 | 全称 | 计算方式 | 可疑性方向 |
|--------|------|----------|------------|
| TSLR | Time Since Last Review | 距离该用户上一条评论的天数 | 低值可疑 |

#### Time2Vec编码（64维）

**原理**：基于论文 "Time2Vec: Learning a Vector Representation of Time"

**公式**：
$$\text{t2v}(\tau)[i] = \begin{cases}
\omega_0 \cdot \tau + \phi_0 & \text{if } i = 0 \text{ (线性项)} \\
\sin(\omega_i \cdot \tau + \phi_i) & \text{if } i = 1, ..., k-1 \text{ (周期项)}
\end{cases}$$

**维度分解**：
- 第0维：线性项（捕捉时间趋势）
- 第1-63维：周期项（捕捉周期性模式）

### 7.6 特征归一化

**方法**：CDF归一化（累积分布函数变换）

**实现**（在 `feature_engineer.py` 的 `_cdf_normalize` 方法中）：

```python
# 计算经验CDF
sorted_values = np.sort(feature_col)
cdf_values = np.searchsorted(sorted_values, feature_col, side='right') / n

# 根据可疑性方向调整
if direction == 'high':      # 值越大越可疑
    normalized = cdf_values
elif direction == 'low':     # 值越小越可疑
    normalized = 1.0 - cdf_values
elif direction == 'extreme': # 极端值可疑
    normalized = np.abs(cdf_values - 0.5) * 2.0
```

import pickle

# 获取时间戳（用于时序划分）

# 时序划分示例
sorted_indices = np.argsort(node_timestamps)
n = len(sorted_indices)
train_end = int(n * 0.6)
val_end = int(n * 0.8)

train_mask = np.zeros(n, dtype=bool)
val_mask = np.zeros(n, dtype=bool)
test_mask = np.zeros(n, dtype=bool)

train_mask[sorted_indices[:train_end]] = True
val_mask[sorted_indices[train_end:val_end]] = True
test_mask[sorted_indices[val_end:]] = True

# 训练时使用整张图作为结构上下文
