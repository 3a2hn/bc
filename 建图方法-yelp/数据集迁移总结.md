# Yelp数据集迁移总结

## 📋 项目概述

本项目将图构建流程从Windows本地环境迁移到Linux服务器环境，并修复了所有依赖和配置问题。

---

## 🔧 主要修改内容

### 1. 创建工具模块 (`utils/`)

由于原项目缺少工具模块，新创建了完整的工具包：

#### `utils/logger.py` - 日志系统
- `setup_logger()` - 设置日志（支持控制台和文件输出）
- `get_logger()` - 获取全局logger实例

#### `utils/data_loader.py` - 数据加载/保存
- `save_pickle()` / `load_pickle()` - Pickle文件操作
- `save_numpy()` / `load_numpy()` - NumPy数组操作

#### `utils/validators.py` - 数据验证
- `validate_graph_quality()` - 验证图数据质量
- `validate_features()` - 验证特征矩阵质量

### 2. 创建预处理模块 (`preprocessor.py`)

新建了完整的Yelp数据预处理器，包含以下功能：

#### 数据加载
- 从CSV文件加载Yelp评论数据
- 支持38,783条评论，20,219个用户，601个商家

#### 数据清洗
- 删除缺失值
- 删除重复评论
- 验证评分范围 (1-5星)
- 标签转换：`1.0` → 正常(1)，`-1.0` → 欺诈(0)

#### 列名处理
- **重命名**：`json_text` → `text`
- **保留**：`json_stars`, `json_user_id`, `json_business_id`

#### 时间特征提取
创建了以下时间相关列：
- `year`, `month`, `day`, `hour`, `dayofweek` - 基础时间特征
- `date` - 日期（不含时间，用于计算每日评论数）
- `year_month` - 年月Period（用于R-T-R边构建）
- `date_unix` - Unix时间戳（秒）
- `timestamp_norm` - 归一化时间戳 [0, 1]

#### ID映射
- `user_idx` - 用户索引 (0-based)
- `business_idx` - 商家索引 (0-based)
- `review_idx` - 评论索引 (0-based，按时间排序)

### 3. 路径配置修改 (`config.py`)

**修改前**（Windows路径）：
```python
DATA_DIR = Path(r'f:\大论文第二部分\yelp数据集时间戳处理\元数据\时间戳元数据')
```

**修改后**（相对路径）：
```python
DATA_DIR = PROJECT_ROOT / 'data'
```

### 4. 特征模块修复 (`features/review_features.py`)

修复了文本列引用：
- `json_text` → `text`（2处）

### 5. 验证器更新 (`utils/validators.py`)

更新了图数据验证器，匹配实际的数据结构：
- `edge_index` → `edges`
- `edge_type` → `edge_attributes`
- `node_timestamp` → `node_timestamps_norm`
- `labels` → `node_labels`

### 6. 图构建器增强 (`edges/graph_builder.py`)

增强了边时间戳验证功能，提供详细的诊断信息：
- 违规数量统计
- 最大违规差值
- 违规比例
- 前5个违规示例

## 🔄 数据流程

```
1. 数据加载 (preprocessor.py)
   ↓
   CSV文件 → DataFrame (38,783条评论)

2. 数据清洗
   ↓
   删除缺失值 → 删除重复 → 验证评分 → 转换标签

3. 特征提取
   ↓
   时间特征 (year, month, date, etc.)
   ID映射 (user_idx, business_idx, review_idx)

4. 图构建 (edges/)
   ↓
   R-U-R边 (用户关联)
   R-T-R边 (时间关联)
   R-S-R边 (评分关联)

5. 特征工程 (features/)
   ↓
   用户特征 (6维)
   产品特征 (6维)
   评论特征 (7-10维)
   时间特征 (2维或64+维)

6. 数据保存 (output/)
   ↓
   graph.pkl, features.npy, labels.npy
```

## 🎯 关键设计决策

### 1. Transductive设定
- 建图阶段构建完整图，不进行train/val/test划分
- 划分逻辑留给训练阶段处理
- 保留所有时间信息供后续使用

### 2. 列名策略
- 保留 `json_*` 前缀列名（edges和features模块依赖）
- 只重命名 `json_text` → `text`（文本处理需要）
- 避免大规模代码修改

### 3. 时间戳处理
- 节点时间戳：归一化到 [0, 100]
- 边时间戳：`max(t_i, t_j)`（较晚一端）
- 保留原始和归一化两种格式

### 4. 标签转换
- 原始：`1.0` (正常), `-1.0` (欺诈)
- 转换后：`1` (正常), `0` (欺诈)
- 符合二分类标准格式

## ⚠️ 注意事项

### 1. 边时间戳验证警告
如果看到"发现X条边的时间戳小于两端节点的最大时间戳"警告：
- 这是正常的浮点精度问题
- 查看最大违规差值和违规比例
- 如果差值很小（<0.01）且比例不高，可以忽略

### 2. 内存使用
- 38K评论数据集内存占用适中
- 图构建过程可能需要4-8GB内存
- 特征工程阶段内存峰值较高

### 3. 运行时间
- 预处理：~5秒
- 图构建：~2-5分钟（取决于边数量）
- 特征工程：~1-3分钟
- 总计：~5-10分钟
